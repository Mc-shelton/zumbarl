# Zumbarl Product Process Coverage

This matrix maps the original ideation notes to the current React surface. It is intentionally implementation-focused so each product pillar can become an end-to-end route, access rule, state model, and service later.

| Pillar | Intended process | Current coverage | Gap | Next implementation step |
| --- | --- | --- | --- | --- |
| Earn | Student discovers work, chooses income or career intent, bids, executes, gets paid, and builds trust. | Opportunities discovery, bids, invites, ongoing projects, service orders, project workspace, activity logs, local Earn service boundary, submitted-work review, approval/revision states, endorsement handoff, payment readiness records, API-ready sync payloads, and profile trust score derived from Earn outcomes. | Bid/project/profile/payment handoff is still locally persisted; payout processing and trust scoring are not backed by real API services yet. | Replace local Earn repository with API-backed bid, project, evidence, review, payout, and trust contracts. |
| Build | Completed work feeds portfolio, endorsements, career readiness, and transition programs. | Profile portfolio, experience, skills, applicant profile, business pipeline views, and local approved-work endorsement updates. | Skill growth, roadmap progress, and unlock rules do not yet react to completed projects. | Add a project completion event model that updates skill growth, roadmap progress, and business endorsement candidates. |
| Learn | Student chooses a roadmap and gets skills, projects, coaching, programs, and exposure. | Typed career-roadmap enrollments, competency and prerequisite graph, persisted checkpoint progress, server-scored assessments, review-gated evidence, baseline profile signals, explainable opportunity matching, roadmap focus, verification, and an API-backed task-oriented Learn workspace. | Automatic evidence ingestion from completed gigs, projects, campaigns and reviews still needs event adapters; business-scoped evidence review, mentor/program inventory and exposure booking remain to be connected. | Publish domain events from completed work into append-only Learn evidence, then add source-owner review rules and live mentorship/exposure inventory. |
| Connect | Students publish stories/status, post tagged content, react/comment/repost, discover people/projects/products, join groups/clubs/events, and contribute to chamas. | Connect route, community sidebar link, story/status creation, tagged post publishing, stateful reactions/comments/reposts, contextual tag actions, group/club/chama discovery, join flow, mock contribution ledger, safety check, and mock state. | Real media upload, realtime feed, moderation service, group admin, wallet/ledger APIs, notifications, and cross-surface tag routing are still mocked. | Connect feed, story, group, tag, moderation, notification, and chama wallet APIs to the mock workflow state. |
| Marketplace | Students create shops, publish products/services, browse listings, buy through cart/checkout, book campus services, order food ahead, track fulfilment, complete campus pickup/drop-off, review, and earn trust scores. | API-backed seller shops and inventory, listing creation/editing and media, unified product/service discovery, appointment requests, order-ahead pickup requests, quote-based services, persisted cart/order data, offers, buyer/provider messaging, checkout, fulfilment status, reviews and disputes. The former standalone campus Services destination now opens the Marketplace service lanes. | Production payment collection, live provider calendars/capacity, eatery menus and modifiers, provider confirmation/rescheduling, automated refunds, and realtime fulfilment notifications are not yet connected. | Add provider operating profiles and slot/menu inventory, then connect production payments, confirmations, fulfilment notifications, cancellations and refunds. |
| Wellness | Students access counseling, anonymous support, wellness programs, and safety reporting. | Help page and safety access keys exist. | Wellness workflows are not represented as pages or state. | Add wellness route, support group cards, counselor booking, and report escalation states. |
| Finance | Student earnings, savings, budgeting, chamas, advances, and payouts connect into survival tools. | Finance access keys and cart checkout exist. | No wallet, payout, budget, savings, or chama finance surface. | Add wallet and budget modules after Earn flow has project/payment state. |
| Business | Businesses post opportunities, review applicants, manage talent pipelines, and endorse students. | Business page, protected business workspace, shared workspace navigation design, applicant profile, interactive applicant tabs, live pipeline stage movement, interview scheduling, role access, shared breadcrumb UI, local business opportunity/review service, award handoff into Earn/project workspace, submitted-work approval/revision/endorsement decisions, and repeat-hire guardrail unlocks. | API persistence, real payment setup, and real mentorship/coaching operations remain mocked or absent. | Replace local business service with API-backed opportunities, applicant review, interviews, award, endorsement, payment, and guardrail contracts. |

## Current Priority

1. Earn API adapters: replace local repository persistence with backend bid, project, evidence, review, payout, and trust endpoints.
2. Business flow consistency: real hiring guardrail operations and payment setup.
3. Learn evidence adapters: publish verified completion events from Earn, Projects, Marketing, portfolio and reviews into the typed competency/evidence graph.
4. Connect API adapters: feed, stories, groups, moderation, and chama contribution ledger.
5. Marketplace API adapters: seller inventory, cart/order, payment, campus handoff, reviews, disputes, and score updates.
6. Finance and wellness once earning/payment events exist.
